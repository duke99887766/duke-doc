# 产品评审检查表

## 使用方式

在中大型需求，或涉及系统联动、状态流转、数据、接口、权限、存量兼容时读取本文件。只应用与当前需求有关的检查项，不输出无意义的空章节。

## 流程与边界

| 维度 | 检查问题 |
| --- | --- |
| 主流程 | 用户如何开始、完成目标，系统如何确认成功？ |
| 替代流程 | 是否存在其他入口、角色、处理路径或人工路径？ |
| 失败流程 | 每个关键步骤失败后，主操作是否保留、回滚或转人工？ |
| 重复与幂等 | 重复点击、重复请求、消息重放是否产生重复结果？ |
| 并发冲突 | 多人或多系统同时修改时，以什么规则处理冲突？ |
| 超时与重试 | 超时后如何展示、重试、查询最终结果并避免重复处理？ |
| 部分成功 | 多对象或多系统只成功一部分时，如何记录、提示和补偿？ |
| 状态边界 | 哪些状态允许操作，哪些状态禁止，终态是否允许恢复？ |
| 数据一致性 | 页面状态、业务数据和上下游数据不一致时如何发现和修复？ |
| 存量兼容 | 历史数据、旧版本客户端和旧业务流程是否受影响？ |

## 交互完整性

| 维度 | 检查问题 |
| --- | --- |
| 入口 | 用户从哪里进入，入口在什么条件下展示？ |
| 默认值 | 默认选择是否符合大多数场景，是否允许人工覆盖？ |
| 可用状态 | 什么条件下启用、禁用或隐藏，禁用原因是否需要展示？ |
| 操作确认 | 高风险、不可逆或批量操作是否需要二次确认？ |
| 过程反馈 | 加载、处理中、成功、失败和部分成功分别如何反馈？ |
| 失败恢复 | 用户能否重试、撤销、转人工或查看失败明细？ |
| 权限差异 | 不同角色看到的入口、字段、按钮和数据范围有何差异？ |
| 操作记录 | 是否记录操作人、时间、前后值、来源和原因？ |

## 研发影响

| 维度 | 需要明确的内容 |
| --- | --- |
| 系统模块 | 涉及页面、服务、任务、配置和管理后台 |
| 上下游 | 触发方、消费方、三方平台和依赖团队 |
| 接口 | 新增或变更接口、兼容策略、错误码和超时重试 |
| 数据 | 字段、枚举、索引、数据表、历史数据和数据迁移 |
| 权限 | 角色权限、数据权限、越权风险和审批要求 |
| 日志审计 | 业务日志、操作日志、变更前后值和审计留痕 |
| 监控告警 | 成功率、失败量、延迟、积压和异常告警 |
| 发布依赖 | 联调方、配置、灰度顺序、回滚条件和负责人 |

## 非功能需求

| 维度 | 检查问题 |
| --- | --- |
| 性能 | 响应时间、数据量、并发量和批处理规模是否有限制？ |
| 可用性 | 依赖不可用时是否降级，核心操作是否仍可完成？ |
| 安全隐私 | 是否涉及敏感数据、脱敏、授权、传输和存储安全？ |
| 兼容性 | 是否兼容历史数据、老流程、客户端和接口版本？ |
| 可恢复性 | 失败后如何重试、补偿、回滚和人工修复？ |
| 可观测性 | 如何通过日志、指标、告警和查询工具定位问题？ |
