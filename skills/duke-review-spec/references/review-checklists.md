# 产品文档评审清单

## 使用方式

根据文档等级和实际风险选择检查项。L1 进行轻量陌生读者检查；L2 检查适用的流程、系统影响和异常；L3 完整检查。只报告真实问题，不输出无意义的“不适用”清单。

## 陌生读者测试

- 是否能识别操作角色、入口、触发条件和前置条件；
- 是否能知道系统执行什么处理，以及何时成功或失败；
- 状态名、字段名、按钮名、提示语和业务对象是否精确；
- 默认、展示、启用、禁用和权限条件是否明确；
- 失败后是保留、回滚、重试、补偿还是转人工；
- 是否必须依赖对话或口头补充才能理解；
- 规则、流程、交互和验收之间是否一致。

## 流程与边界

| 维度 | 检查问题 |
| --- | --- |
| 主流程 | 用户如何开始、完成目标，系统如何确认成功？ |
| 替代流程 | 是否存在其他入口、角色、处理路径或人工路径？ |
| 失败流程 | 关键步骤失败后，主操作是保留、回滚还是转人工？ |
| 重复与幂等 | 重复点击、请求或消息是否产生重复结果？ |
| 并发冲突 | 多人或多系统同时修改时如何处理？ |
| 超时与重试 | 超时后如何展示、查询、重试并避免重复？ |
| 部分成功 | 多对象或多系统只成功一部分时如何记录和补偿？ |
| 状态边界 | 哪些状态允许或禁止操作，终态是否可恢复？ |
| 数据一致性 | 页面、业务数据和上下游不一致时如何发现和修复？ |
| 存量兼容 | 历史数据、旧流程和旧接口是否受影响？ |

## 交互完整性

| 维度 | 检查问题 |
| --- | --- |
| 入口 | 从哪里进入，什么条件下展示？ |
| 默认值 | 是否符合主要场景，是否允许人工覆盖？ |
| 可用状态 | 何时启用、禁用或隐藏，原因是否展示？ |
| 操作确认 | 高风险、不可逆或批量操作是否需要确认？ |
| 过程反馈 | 处理中、成功、失败和部分成功如何反馈？ |
| 失败恢复 | 是否支持重试、撤销、转人工或查看明细？ |
| 权限差异 | 不同角色的入口、字段、按钮和数据范围有何差异？ |
| 操作记录 | 是否需要记录操作人、时间、前后值、来源和原因？ |

## 研发与非功能影响

按需检查系统模块、上下游、接口、数据、权限、日志审计、监控告警和发布依赖，以及性能、可用性、安全隐私、兼容性、可恢复性和可观测性。

不得仅因使用已有系统联动、状态或接口机制就要求完整专项方案。

## 验收追溯

- 每条核心规则是否有可观察结果；
- `AC-xxx` 是否引用对应 `R-xxx`；
- 验收是否覆盖真实存在的禁止、失败、边界或权限差异；
- 是否存在验收要求超出需求范围，或需求规则没有验收覆盖。

## 模糊表达

检查“支持、相关、正常、合理、必要时、尽量、默认处理、及时、根据实际情况、视情况、等”等表达是否缺少精确条件和结果。

## 输出格式

| 优先级 | 文档位置 | 问题 | 影响 | 修改建议 |
| --- | --- | --- | --- | --- |

优先级使用 P0、P1、P2。问题描述应指出具体位置、产生何种不同理解，以及建议改成什么。
