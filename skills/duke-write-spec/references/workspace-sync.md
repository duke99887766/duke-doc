# 文档工作区同步约定

## 读取条件

仅在用户要求创建/更新本地文档、存在 `docs/README.md`、需要维护索引，或文档包含原型入口时读取。只做临时分析或不写入文件时无需读取。

## 写入前

- 先读取 `docs/README.md`、对应项目导航、当前有效文档和专项规则；只读取目标主题和直接关联资产，不扫描整个文档库。
- 确认用户授权的文件范围；未授权资产列为待同步。
- 同一阶段默认只保留一份规范性文档，不创建“最终版”“最新版”、快照或版本副本。

## Frontmatter 最小事实字段

```yaml
---
文档类型: 产品需求文档
文档状态: 草稿
需求阶段: 需求中
所属模块:
负责人:
优先级:
版本: V1.0
创建时间: YYYY-MM-DD
更新时间: YYYY-MM-DD
计划上线:
关联项目:
原型状态: 无原型
原型文件:
原型预览:
协作方:
标签:
  - 产品需求
---
```

Frontmatter 只保存事实字段。`负责人`、优先级、计划上线、关联项目和协作方无法确认时留空；创建时间首次写入后保持不变，实质内容或状态变化时更新 `更新时间`。

- `文档状态`：草稿、评审中、生效中、待更新、已归档；
- `需求阶段`：需求中、待开发、开发中、联调中、验收中、已上线、已取消；
- `原型状态`：无原型、草稿、待同步、已同步、已废弃；
- 原型状态不是“无原型”时必须填写 `原型文件`，正文前 60 行提供可点击入口；稳定可访问时才填写 `原型预览`。

## 同步与校验

- README 索引、Frontmatter 和正文首屏研发快速入口属于同一文档阶段。
- 有原型时维护 `原型状态`、`原型文件` 和可选的 `原型预览`；只有原型覆盖当前有效规则并通过校验才标记“已同步”。
- 更新记录如需维护，统一放在正文最后。
- 一轮批量编辑完成后再执行专项校验和一次 `verify-workspace.ps1 -ChangedOnly`；阶段收口时才全量校验。
