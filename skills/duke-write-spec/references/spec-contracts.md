# 文档输出契约

## 1. 选择规则

优先使用输入中指定的等级；直接调用且未指定时按失败后果、可逆性、系统影响和用户要求选择最轻的可用等级：

- L1：单页面、单配置项或已有机制上的小范围修改；
- L2：多个模块、状态、对象或已有上下游联动；
- L3：新增关键链路，或涉及资金、安全、合规、不可逆迁移和重大一致性风险。

不要仅因出现系统联动、状态流转或接口就选择 L3。用户要求简单版时优先 L1，重大风险除外。

## 2. 唯一规范性文档

- 用户要求“简单版”“简化需求”或“小改说明”时，默认以 L1 文档作为本期唯一规则源。
- 不先创建完整 PRD 再自动补一份简化版，也不因已有同主题文档默认维护两套确定性规则。
- 只有用户明确要求面向不同读者保留两个层级时，才同时维护规范性文档和简化摘要；摘要在首屏链接唯一规则源，只引用适用的 `R-xxx`/`AC-xxx`，不复制完整规则表、验收表或版本记录。
- 已有完整文档仍承载其他阶段时，本期文档只写增量并关联上位文档，不复制整份历史规则。

## 3. 共同口径

- 只有状态账本中标记为“已确认业务规则”的内容可以写成确定结论。
- 原型方案、实现默认、数据发现和建议必须保持原性质；会改变业务结果时返回确认。
- 已废弃规则不得继续出现在生效章节；必要时仅在更新记录中说明替代关系。
- README 索引、Frontmatter 和原型入口维护属于同一文档阶段，不单独触发编排。

## 4. 研发快速入口

原型存在时必须在正文前 60 行提供入口；L1 使用单行入口，L2/L3 使用三列表格。更新记录不参与首屏结构，统一放在正文最后。无原型时不输出空入口，Frontmatter 使用 `原型状态: 无原型`。

## 5. 关联资产与授权

只有资产登记、文件内容、规则引用、阶段定义或用户说明能够证明覆盖关系时才直接更新。主题相近但覆盖范围未知的资产标记“需核对”；未授权修改的资产只报告待同步，不自行写入。

## 6. 写入后自动校验

一轮批量写入完成后，对每个变更 Markdown 文档执行一次：

```powershell
python scripts/check_requirement_docs.py <文档路径>
```

按需增加 `--require-frontmatter`、`--index <README路径>`、`--expect-update-date YYYY-MM-DD` 和 `--repo-root <仓库目录>`。阻塞错误必须修复；警告按 `[本文定义]`、`[规则追溯]`、`[原型关联]` 和 `[跨资产]` 分类，并在交付说明中列出。
