# 产品需求编排

## 核心职责

- 判断本轮是单阶段、C0/C1/C2 变更，还是明确的端到端交付。
- 选择专业 Skill，传递增量需求包，控制确认节点和必要回环。
- 根据风险和用户偏好选择 L1、L2 或 L3，不因“有联动”机械升级。
- 在长周期需求中维护需求状态账本的增量口径，不在每轮复制完整账本。
- 在 C2 规则变化后识别受影响资产并汇总一致性结果。
- 汇总最终交付，不重复专业 Skill 的模板和检查清单。

## 触发与快速路由

默认优先使用单个专业 Skill：

| 请求 | 默认路由 |
| --- | --- |
| 修改或新建一份 PRD/Spec，含 README 索引维护 | `duke-write-spec` |
| 修改 HTML 原型或只做视觉调整 | `duke-build-requirement-prototype` |
| 生成验收标准 | `duke-write-acceptance` |
| 评审已有文档 | `duke-review-spec` |
| 仅根据实现证据验收 | `duke-check-implementation` |
| 模糊需求或存在实现分歧 | `duke-interview-requirement` |
| Excel/CSV 历史数据验证 | `duke-analyze-requirement-data` |

只有以下情况进入编排：

- 用户明确调用 `$duke-doc`；
- 明确要求两个及以上独立需求阶段；
- 已确认业务规则变化，且需要同步两个及以上不同类型的规则承载资产。

README 索引、同一文档的 Frontmatter 或原型入口维护不算独立阶段。用户只说“文档落地”“更新文档”时，已有信息足够就直接路由到 `duke-write-spec`。

## 参考资料按需读取

不要默认完整读取全部参考文件。使用本 Skill 后只读取与当前模式相关的资料：

| 参考 | 读取条件 |
| --- | --- |
| `references/routing.md` | C1/C2、跨阶段或路由边界不清时 |
| `references/requirement-ledger.md` | 多轮规则变化、状态账本恢复或上下文压缩时 |
| `references/asset-sync.md` | C1/C2 确需跨资产同步时 |
| `references/phase-version.md` | 多阶段、已上线续期或版本边界变化时 |
| `references/history-compatibility.md` | 历史数据、存量数据、旧逻辑、迁移或新旧规则并存时 |

进入某一阶段时只完整读取对应专业 Skill；其 reference 继续遵循该 Skill 标明的条件。已在本轮读取且文件未发生变化的资料视为有效，不重复读取。

## 变更和阶段门控

先判断变化性质，再决定执行范围：

| 模式 | 处理范围 | 默认不做 |
| --- | --- | --- |
| C0 视觉微调 | 原型目标区域、静态检查和一次浏览器检查 | 不启动 `duke-doc`，不读 PRD，不生成资产清单 |
| C1 展示/交互规则 | 原型、直接承载规则的文档或验收资产及必要校验 | 不自动执行完整访谈、全量传播或全文评审 |
| C2 业务规则变更 | 用户确认后生成影响资产清单并执行跨资产一致性检查 | 不在未确认时改写业务事实 |
| 端到端交付 | 仅执行用户要求且确有必要的阶段 | 不默认补齐所有阶段 |

默认阶段门控：

- 访谈：只有缺口会改变价值、范围、核心规则或验收结果时进入；信息足够时直接建立简要需求包。
- 数据分析：只有用户提供数据或明确要求数据验证时进入。
- 原型：只有需要验证页面结构或交互时进入。
- 验收标准：用户要求、交付物明确需要 AC，或当前规则没有可执行验收时进入；已有 AC 不重复生成。
- 文档输出：用户要求创建或更新正式文档时进入。
- 文档评审：用户明确要求、L3、高风险规则或发现结构性冲突时进入；普通 L1/L2 不自动全面评审。
- 实现验收：只有提供实现证据或明确要求时进入。

## 编排流程

1. 分类本轮请求为单阶段、C0/C1/C2 或端到端，并确认写入授权。
2. 恢复本轮目标资产和已有有效规则；只有范围变化、资产外部修改或追溯不清时才重读完整资产。
3. 建立增量交接包，只传递本轮新增、修改、废弃的 `R/Q/D/AC`、目标资产、阻塞项和校验结果。
4. 按阶段门控调用专业 Skill，发现会改变业务结果的新问题时返回访谈确认。
5. 完成一轮批量写入后，执行对应专项校验，再执行一次 `verify-workspace.ps1 -ChangedOnly`；阶段收口或批量治理时才运行全量校验。
6. 最终只汇总已更新资产、未同步资产、阻塞项、校验结果和仍待确认事项，不复制完整中间报告。

## 增量交接包

专业 Skill 之间优先传递以下字段：

```text
本轮目标阶段：
本期范围/明确排除：
本轮新增规则：
本轮修改或废弃规则：
本轮关闭问题：
目标资产和直接受影响组件：
需要重新验证的 AC：
保持不变的规则范围：
阻塞项/待确认项：
最近一次校验：
```

后续 Skill 不得重新发明或静默改变已确认业务事实；建议、原型方案、实现默认和数据发现必须保持原性质。

## 长任务恢复包

长任务只在阶段切换、`R/Q/AC` 状态变化、目标资产变化、完成写入/校验或即将压缩上下文时刷新一个不超过 20 行的任务内恢复包。普通问答和重复检查不刷新。恢复包仅用于当前 Codex 任务，不创建产品文档快照、版本副本或本地文档版本管理。

恢复时先检查用户新输入是否改变范围，再读取恢复包指向的目标片段；文件已被外部修改或证据失效时放弃缓存并重新读取相关资产。

## 资产传播和确认

- C0 不生成影响资产清单；C1 只登记直接承载变化的资产；C2 才执行完整影响识别。
- 只有资产登记、内容、规则引用、阶段定义或用户说明能够证明覆盖关系时才直接更新；不确定时标记“需核对”。
- 只有用户授权的文件才写入；原型演示细节、实现默认和数据建议不得传播为正式业务规则。
- 以下情况才暂停确认：核心价值/范围/方案有多种方向、缺口会导致不同实现结果、证据与规则冲突，或评审/验收需要改变业务事实。

## 写入边界

只有用户明确要求创建或更新文件时才写入：PRD、专项规则和索引由 `duke-write-spec` 处理；验收标准由 `duke-write-acceptance` 处理；HTML 原型由 `duke-build-requirement-prototype` 处理；评审和实现验收报告也仅在用户要求时保存。
