# 实现证据与验收契约

## 证据类型

| 证据 | 可证明内容 | 主要限制 |
| --- | --- | --- |
| 页面截图或录屏 | 可见页面、字段、按钮、状态和文案 | 通常不能证明后台处理和数据结果 |
| 配置内容 | 实际配置值、规则和启用状态 | 不能单独证明运行时行为 |
| 代码 | 存在实现逻辑及处理分支 | 不能单独证明已部署或运行正确 |
| 接口请求与响应 | 接口输入、输出、错误码和部分处理结果 | 可能不能覆盖异步或后续链路 |
| 数据查询 | 字段、状态、关联关系和落库结果 | 需要明确环境、时间和样本 |
| 测试记录 | 已执行场景和实际结果 | 需要能追溯需求、版本和环境 |
| 环境操作结果 | 端到端实际表现 | 需要说明环境、账号和前置数据 |

优先使用能够直接证明需求结果的证据；只有间接证据时说明推断范围。

## 验收结论

| 结论 | 判定标准 |
| --- | --- |
| 符合 | 条件、处理和结果与需求一致，并有充分证据 |
| 部分符合 | 已实现部分规则，但存在缺失、偏差或覆盖不完整 |
| 不符合 | 实现行为与需求明确冲突，或关键能力未实现 |
| 无法验证 | 没有足够证据判断，不代表已实现或未实现 |

## 输出格式

```markdown
# 需求实现验收

## 1. 验收范围

## 2. 需求与实现对照

| 规则编号 | 需求规则 | 实现证据 | 验收结论 | 差异或风险 |
| --- | --- | --- | --- | --- |

## 3. 未覆盖或无法验证项

## 4. 验收结论
```

没有证据时，明确需要补充的截图、配置、接口结果、代码位置、数据查询、测试记录或环境结果。

## 证据冲突

- 多份证据相互冲突时，说明各自来源、环境和时间，不自行选择有利证据。
- 需求版本与实现版本不一致时，先明确验收基线。
- 需求规则本身存在歧义时，将结论标为“无法验证”或“部分符合”，并建议先统一需求口径。
- 只验证用户纳入范围的规则，不将通用代码质量问题混入需求验收结论。
