# 需求实现验收

## 工作目标

根据需求规则和可验证证据判断实际实现是否符合要求，不以猜测替代证据。

## 输入要求

至少需要：

- 最终需求文档或明确的业务规则；
- 页面截图、配置、代码、接口结果、测试记录或环境结果中的一种或多种实现证据。

只有需求没有证据时，可以提取待验收规则，但不得给出已实现结论。只有证据没有需求口径时，说明无法判断符合性。

## 工作流程

正式验收前读取 [实现证据与验收契约](references/evidence-contract.md)。

1. 从最终需求提取可独立验证的规则，保留 `R-xxx` 编号。
2. 为每条规则定位直接或间接实现证据。
3. 对照触发条件、系统处理和可观察结果。
4. 使用“符合、部分符合、不符合、无法验证”给出结论。
5. 说明差异、风险和需要补充的证据。
6. 汇总阻塞验收的问题和整体结论。

## 证据原则

- 没有证据时不得推断已经实现。
- 截图只能证明可见页面状态，不能单独证明后台处理、数据落库或异常链路。
- 代码只能证明存在实现逻辑，不能单独证明部署状态和运行结果。
- 测试记录应能追溯到需求规则和测试环境。
- 需求与实现存在冲突但需求口径也有歧义时，先标记口径问题，不武断判定实现错误。

## 输出边界

- 不重新设计验收标准。
- 不修改需求规则。
- 不自动扩展为通用代码质量、安全或架构评审。
- 不编写或修改实现代码。
