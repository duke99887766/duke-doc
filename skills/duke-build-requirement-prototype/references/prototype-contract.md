# 原型输出与验收契约

## 1. 页面类型选择

| 需求 | 建议结构 |
| --- | --- |
| 单一录入流程 | 单页表单或步骤式表单 |
| 列表与详情联动 | 列表、筛选区、详情抽屉或页签 |
| 历史记录 | 紧凑时间线或记录卡片 |
| 多场景差异 | 页面内场景切换器或查询参数，不复制独立文件 |
| 确认轻交互 | 原生HTML、CSS和JavaScript单文件原型 |

优先采用能最小成本验证核心规则的结构，不为展示完整度添加无需求依据的模块。

## 2. 规则输入分层

| 输入性质 | 原型处理 |
| --- | --- |
| 已确认业务规则 | 必须实现；关键组件标记 `data-requirement-id` |
| 原型方案 | 可演示；交付时单独说明 |
| 实现默认 | 只补足非业务交互；不得改变业务结果 |
| 数据发现 | 用于构造样例或风险场景；不得当成全量事实 |
| 待确认问题 | 保持中性或同时演示可选方案，不擅自拍板 |

## 3. 更新既有原型

1. 读取完整HTML，识别页面结构、公共样式、脚本状态和既有场景。
2. 将本轮变更映射到目标组件，避免全文件重写。
3. 保留用户已有且与本次需求无关的内容。
4. 删除组件前检查是否仍被其他场景或脚本引用。
5. 修改字段、枚举或可见条件时同步检查回显、校验、提交和时间线展示。

## 4. 场景覆盖

按需求选择必要场景，不机械覆盖全部：

- 业务对象差异：三方订单、系统订单或其他订单；
- 数据状态：空值、有值、历史数据异常；
- 操作阶段：首次进入、编辑中、提交成功、部分失败；
- 权限状态：可操作、只读、无权限；
- 内容状态：空列表、有记录、筛选无结果、分页；
- 联动状态：联系方式与联系结果、状态与原因、勾选与展开。

## 5. 交互与视觉要求

- 保持明确的主次层级和紧凑但可读的信息密度。
- 关键状态、优先级、预约时间和创建人等突出信息由需求决定，不默认全部强调。
- 标签使用 `for` 关联字段；图标按钮提供 `aria-label`；图片提供 `alt`。
- 按钮明确 `type`，避免表单内误提交。
- 隐藏内容同时处理可见性和交互状态，避免不可见控件仍可聚焦。
- 错误、失败和只读状态必须有可观察反馈。

## 6. 追溯规则

示例：

```html
<section data-requirement-id="R-012 R-018">
  ...
</section>
```

- 多个编号使用空格分隔。
- 只标记承载业务行为或业务信息的关键节点。
- 规则变更后检查原型中是否仍残留已废弃编号。

## 7. 验收顺序

1. 运行静态检查脚本；
2. 检查关键场景是否可进入；
3. 操作主要交互并观察状态回显；
4. 检查不同宽度下的遮挡和溢出；
5. 对照本轮规则编号检查遗漏；
6. 输出未完成的视觉检查或待确认项。
