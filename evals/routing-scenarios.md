# 路由回归场景

| 场景 | 预期 Skill 或流程 | 不应发生 |
| --- | --- | --- |
| “我有个模糊需求，帮我一起梳理” | `duke-interview-requirement` | 直接输出完整 PRD |
| “结合这两份历史Excel检查字段兼容风险” | `duke-analyze-requirement-data` | 直接把样本结论写成业务规则 |
| “根据已确认规则做一个浏览器可预览原型” | `duke-build-requirement-prototype` | 扩展为生产前端实现 |
| “根据这些规则写一份简单 Spec” | `duke-write-spec`，L1 | 启动完整需求访谈 |
| “把这些规则转成验收标准” | `duke-write-acceptance` | 重写整份 PRD |
| “评审这份 PRD 有什么问题” | `duke-review-spec` | 核对代码实现 |
| “根据 PRD 和截图检查是否实现” | `duke-check-implementation` | 没有证据时判定符合 |
| “按 `$duke-doc` 从讨论到文档完成” | 访谈按需 → 数据/原型验证按需 → 验收标准按需 → 文档 → 风险触发评审 | 所有阶段无条件执行，或所有工作仍由编排 Skill 自己完成 |
| “现有订单联动增加一条固定规则，简单版” | L1 或风险可控时 L2 | 仅因系统联动升级 L3 |
| “新增结算链路并迁移历史数据” | `duke-doc`，L3 | 使用轻量 Spec |
| “分析竞品定价” | 未提供明确来源且不要求入库时不触发本 Skill 集合 | 使用 `duke-doc` |
| “把这个竞品官网页面整理并保存到研究资料库” | `duke-capture-web-research`，L1 | 直接输出 PRD 或整篇复制网页 |
| “对比这三个平台规则页面，形成研究结论并入库” | `duke-capture-web-research`，L2 | 混淆来源事实和产品判断 |
| “总结这个网页回答我的问题即可，不用保存” | 通用网页阅读或问答 | 默认创建研究笔记 |
| “根据已入库的竞品研究梳理一个新需求” | `duke-interview-requirement` | 继续由研究 Skill 编写正式 PRD |
| “只把订单号前的平台图标向左移动 4px” | C0 布局微调，仅使用 `duke-build-requirement-prototype` | 启动 `duke-doc` 或同步正式文档 |
| “接口自动、接口手动保留生产信息列表，链接下单和线索转交隐藏列表” | C1 展示规则；同步原型及直接关联的 `R-xxx`/`AC-xxx` | 仅当作视觉调整或无证据扩散到全部资产 |
| “四种生产方式的字段语义和订单侧输出规则都调整” | C2 业务规则变更，使用 `duke-doc` 完整传播 | 只修改原型 |
| “这个需求简单，给我一份简化文档” | `duke-write-spec`，L1 且默认作为唯一规范性文档 | 先创建完整 PRD 再补简化版 |
| “打开本地 HTML 原型并检查交互” | 使用 `preview_prototype.py` 启动 localhost 后验收 | 默认使用 `file://`，受限后直接跳过视觉检查 |
| “已有规则已经确认，进行文档落地并更新项目 README” | `duke-write-spec`，README 作为同一文档阶段的配套索引 | 仅因同时修改两个文件启动 `duke-doc` |
| “现有 L1 文档补充一条已确认规则” | `duke-write-spec` 增量更新并执行专项校验和一次 `ChangedOnly` | 自动重新访谈、重建全部 AC 或全文评审 |
| “新增规则需要同步 PRD、HTML 原型和验收标准” | C2，使用 `duke-doc` 生成影响资产清单并同步不同资产类型 | 只修改主文档或无条件扫描整个文档库 |
| “表格列宽和按钮间距一起微调” | C0，批量修改后静态校验和一次浏览器检查 | 每个样式修改后分别启动预览和全量校验 |

## 职责边界检查

- 访谈 Skill 只输出需求包，不输出正式 PRD。
- 数据分析 Skill 只输出带来源的数据发现、风险和问题，不直接修改业务规则。
- 原型 Skill 只实现已确认规则和标记清晰的原型假设，不制作生产代码。
- 验收 Skill 不修改业务规则。
- 文档 Skill 不开展完整访谈，不独立设计详细验收。
- 评审 Skill 默认只输出问题，不静默改变业务口径。
- 实现验收没有证据时输出“无法验证”。
- 编排 Skill 不复制各专业 Skill 的详细模板和检查清单。
- 网页研究 Skill 负责来源采集和研究入库，不直接生成正式 PRD。
- C0 不创建规则编号或影响资产清单；C1 只同步直接承载资产；C2 才执行完整传播。
- 同一阶段默认只有一份规范性文档，简化摘要不复制维护完整规则和验收表。
- README 索引、Frontmatter 和原型入口属于文档阶段配套资产，不单独触发 `duke-doc`。
- 普通 L1/L2 文档落地不自动生成全部验收标准或执行全文评审。
- 同一轮批量修改只执行一次专项校验和一次 `ChangedOnly`，阶段收口才全量校验。

## 追溯检查

- 需求规则使用 `R-xxx`。
- 验收场景使用 `AC-xxx` 并引用 `R-xxx`。
- 实现验收继续使用相同的 `R-xxx`。
- 后续阶段不得静默改变已确认规则。
- 数据发现使用 `D-xxx`，经用户确认后才转换为 `R-xxx`。
