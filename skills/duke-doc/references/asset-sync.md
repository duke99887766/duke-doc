# 资产变更传播协议

## 1. 触发条件

先按 [路由与交接协议](routing.md) 判断变更等级：

- C0 视觉微调不生成影响资产清单，只修改和校验原型；
- C1 展示或交互规则只登记直接承载对应规则的原型、验收和规范性文档；
- C2 业务规则变更必须生成完整影响资产清单。

以下变化按 C2 处理：

- 新增、修改、替代或废弃业务规则；
- 调整阶段范围或版本边界；
- 修改字段、状态、枚举、默认值、权限、异常处理或历史兼容规则；
- 原型验证或数据分析推翻原有假设。

文案含义、可见条件、操作结果或业务反馈变化至少按 C1 处理。间距、颜色、图标位置、换行和无业务含义的装饰保持 C0，不得仅为形式一致同步正式文档。

文档名称、位置、README 索引、Frontmatter 或原型入口变化属于资产元数据维护；只更新直接链接和索引，不因其本身升级为 C2。

## 2. 资产登记

对项目中已经存在或用户要求创建的资产登记：

| 字段 | 示例 |
| --- | --- |
| 资产类型 | HTML原型、PRD、专项规则、验收标准、README索引 |
| 文件路径 | 使用实际绝对路径或仓库相对路径 |
| 覆盖范围 | 第一阶段、第二阶段2A、记录分类等 |
| 规则编号 | 该资产承载的 `R-xxx` |
| 当前状态 | 已同步、待同步、不适用、仅供参考 |
| 待执行动作 | 新建、更新、校验链接、更新索引等 |

资产名称或主题相近不等于承载同一规则。覆盖范围必须来自资产登记、文档内容、规则引用、阶段定义或用户明确说明；无法证明时记录为“需核对”。

## 3. 传播步骤

1. 从本轮已确认变更中提取涉及的规则编号；C0 不进入本协议。
2. 查询资产登记或读取目标片段，列出有证据直接承载该规则的资产；不因主题相近批量扫描全部文档。
3. 根据术语、枚举、阶段、链接和追溯关系补充间接受影响资产；只有主题相近但覆盖范围未知时标记“需核对”。
4. 用户已授权写入时，调用对应专业 Skill 修改资产；未授权时只列出待同步项。
5. HTML原型创建或更新后，仅在确有对应 PRD 时同步其`原型状态`、`原型文件`、可选的`原型预览`及正文首屏研发快速入口。
6. 完成一轮批量修改后统一校验直接受影响资产；不为每个小改动单独触发全量传播或工作区校验。

## 4. 一致性检查

- 规则编号和规则内容一致；
- 页面字段、状态、默认值和可见范围与正式规则一致；
- 原型假设没有被误写成确定规则；
- 验收标准仍覆盖变更后的业务结果；
- 阶段范围和版本号没有互相覆盖；
- Frontmatter、更新时间、README索引和关联链接同步；
- 原型文件存在，正文前60行可直接进入原型，且“已同步”原型不引用已废弃规则；
- 已废弃规则未继续以有效规则出现；
- 未授权修改的资产明确标记“待同步”。
- 未确认覆盖范围的资产保持“需核对”，不得标成“直接更新”。

## 5. 边界

- 不扩大用户授权的写入范围。
- 不为保持表面一致而修改尚未确认的业务规则。
- 不覆盖用户已有且与本次需求无关的文件改动。
- README 索引、Frontmatter 和原型入口维护不单独触发跨资产编排。
