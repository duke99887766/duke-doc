# 历史兼容检查协议

## 1. 使用条件

需求涉及历史数据、旧页面、旧接口、旧枚举、迁移、合并展示或新旧逻辑并存时使用。根据实际风险选择检查项，不为简单需求制造迁移工作。

## 2. 数据与字段

- 空值、字面量 `null`、空字符串和默认占位值是否语义一致；
- 编码是否存在前导零、位数错误、大小写或历史别名；
- 字段是否在历史阶段发生过语义变化；
- 新字段能否可靠回填，不能回填时如何展示；
- 创建人、来源、时间、附件等审计字段是否完整；
- 时间格式、时区和相同时间下的稳定排序；
- HTML、富文本、转义字符和原始备注如何安全回显。

## 3. 枚举与分类

- 未知、停用、异常或新增枚举如何兜底；
- 原始枚举与标准分类是否需要分层保留；
- 历史编码纠错是迁移、映射兼容还是原文展示；
- 同一编码是否在不同来源或时期代表不同语义；
- 统计和筛选是否会因新旧分类口径产生跳变。

## 4. 记录与身份

- 新记录必填约束是否错误追溯到旧记录；
- 人工与系统身份如何判断，系统账号是否使用指定ID；
- 旧记录缺少关联对象时是补关系、按辅助键查询还是无法展示；
- 联系电话、订单号等辅助查询键为空、重复或变更时如何处理；
- 历史记录是否允许编辑、删除、撤回、作废或迁移。

## 5. 附件、同步与状态

- 附件地址、类型、时长、文件名或证明材料不完整时如何回显；
- 同步布尔值、平台标志、失败状态是否存在语义歧义；
- 新旧状态能否直接比较，终态和异常态如何展示；
- 部分成功、补偿、重试和重复消息是否产生重复记录。

## 6. 处理策略

每类历史问题明确选择一种策略：

| 策略 | 适用说明 |
| --- | --- |
| 批量迁移 | 数据可可靠转换，且业务收益覆盖迁移风险 |
| 查询时映射 | 保留原值，通过映射层统一展示或筛选 |
| 原文展示 | 无法可靠解释或转换，优先保留历史事实 |
| 仅兼容读取 | 新逻辑不再产生，但旧数据仍可查看 |
| 不处理 | 明确接受无法查询、无法补全或不展示的边界 |

不得只写“兼容历史数据”。必须说明对象、策略、新旧差异、失败兜底和是否影响统计。
