# 路由与交接协议

## 1. 路由判断

默认选择单个专业 Skill；README 索引、Frontmatter 或原型入口维护属于同一文档阶段：

| 用户请求 | 执行方式 |
| --- | --- |
| 模糊想法或存在实现分歧 | `duke-interview-requirement` |
| 历史明细、Excel/CSV 验证需求规则 | `duke-analyze-requirement-data` |
| 已确认规则，需要浏览器可预览页面 | `duke-build-requirement-prototype` |
| 已确认规则，需要写或更新 PRD/Spec | `duke-write-spec` |
| 需要验收标准或测试场景 | `duke-write-acceptance` |
| 已有 Spec/PRD，需要文档评审 | `duke-review-spec` |
| 同时提供需求与实现证据 | `duke-check-implementation` |
| 明确调用 `$duke-doc`、要求两个及以上独立阶段，或 C2 规则变化需同步两个及以上资产类型 | 进入编排 |

以下请求不因“相关资产存在”自动进入编排：只更新一份文档、只维护 README 索引、只修改一个原型、只生成 AC，或只做一次实现验收。

## 2. 交付等级

| 维度 | L1 轻量 Spec | L2 标准需求 | L3 完整 PRD |
| --- | --- | --- | --- |
| 修改范围 | 单页面、单配置项或已有规则小改 | 多页面、模块或对象联动 | 多个核心系统或业务域 |
| 方案状态 | 已基本确定 | 主方案明确，需梳理分支 | 存在重大取舍或尚未收敛 |
| 数据影响 | 无迁移或普通字段变更 | 有限存量兼容 | 大规模、复杂或不可逆迁移 |
| 风险 | 可恢复且影响有限 | 一致性、权限或依赖风险可控 | 资金、安全、合规或重大一致性风险 |

优先判断失败后果、可逆性和是否引入新机制，不按命中项机械计分。用户要求简单版时优先 L1，除非存在重大风险并说明升级原因。

## 3. 变更分级与默认范围

| 等级 | 判断标准 | 默认执行范围 | 升级条件 |
| --- | --- | --- | --- |
| C0 视觉微调 | 间距、颜色、对齐、图标位置、换行和无业务含义的装饰 | 原型目标区域、静态检查、一次浏览器检查 | 文案含义、可见条件、操作结果或业务反馈变化 |
| C1 展示或交互规则 | 已确认信息的展示位置、可见条件、按钮行为、反馈或场景差异变化，但不改变业务事实 | 原型、直接承载规则的 `R/AC` 资产及必要校验 | 字段语义、状态、权限、流程、接口输出或历史兼容变化 |
| C2 业务规则变更 | 新增、修改、替代或废弃业务规则，或改变字段、状态、权限、流程、异常、接口及历史兼容 | 用户确认后生成影响资产清单并执行跨资产一致性检查 | 无 |

无法判断 C0/C1 时，以“是否会让研发实现出不同业务结果”为准；会则按 C1，否则按 C0。C0 不新增规则编号或影响资产清单。

## 4. 阶段门控

- 访谈只在缺口会改变价值、范围、核心规则或验收结果时进入；信息足够时建立简要需求包。
- 数据分析只在用户提供数据或明确要求数据验证时进入。
- 原型只在需要验证页面结构或交互时进入。
- 验收标准只在用户要求、交付物需要 AC、或现有规则缺少可执行验收时进入；已有 AC 不重复生成。
- 文档评审只在用户明确要求、L3、高风险规则或发现结构性冲突时进入；普通 L1/L2 不自动全文评审。
- 实现验收只在提供实现证据或明确要求时进入。

## 5. 增量交接

专业 Skill 之间只传递当前阶段需要的增量：

| 字段 | 内容 |
| --- | --- |
| 本轮目标 | 阶段、范围、明确排除 |
| 规则变化 | 新增、修改、废弃的 `R-xxx` |
| 问题变化 | 关闭或新增的 `Q-xxx`；数据发现沿用 `D-xxx` |
| 验收变化 | 需要重新验证的 `AC-xxx` |
| 目标资产 | 文件、页面、DOM/组件或章节 |
| 不变范围 | 保持有效且无需重读的规则或资产 |
| 阻塞项 | 会导致不同实现结果的缺口 |
| 最近校验 | 专项校验和工作区校验摘要 |

后续 Skill 不得重新编号、静默改变已确认事实或复制不变规则。完整需求包或状态账本快照只在阶段收口、交接或用户明确要求时输出。

## 6. 校验节奏

写入类任务完成一轮批量修改后：

1. 执行对应专项校验；
2. 修复阻塞错误；
3. 执行一次 `verify-workspace.ps1 -ChangedOnly`；
4. 阶段收口或批量治理时再执行一次全量校验。

不要在每个小修改后重复运行工作区校验；既有且未受影响的警告只在最终结果中汇总。

## 7. 组合流程

### 端到端需求交付

只执行用户要求且确有必要的阶段：访谈（按需）→ 数据/原型（按需）→ 验收（按需）→ 文档（按需）→ 评审（按风险）→ 资产一致性检查。

### 原型或数据触发回访

已确认规则 → 验证 → 发现冲突 → 更新待确认项 → 用户确认 → 同步直接受影响资产。

### 已有文档修订

文档评审（按需）→ 用户确认业务变更 → 文档输出 → 直接关联资产校验。

### L1 快速流程

已有信息足够时：简要需求包 → L1 文档或原型 → 专项校验 → `ChangedOnly`；不自动补齐完整访谈、AC、全文评审或全量传播。
